# arm64-native escape paths, from hardware counters

2026-09-23. Neoverse N2 (Azure, 2 vCPU), Linux 6.17, Go 1.27.1. Baseline:
`3cb3ae9`. Decisions made on per-op core cycles from `bench/counters.py`, which
now counts the Armv8 PMUv3 events this VM exposes; claims below are confirmed by
alternating, pinned timing series (`bench/compare.py`, n=6 × 0.5 s, CPU 1).

**amd64 is unchanged, instruction for instruction.** Every function of the
package compiles to the same amd64 machine code as at the baseline
(`bench/asmdiff.py`: 27 package functions identical, 0 different), so no x86
claim is made or needed. Everything below is arm64.

## What this core is (measured, not from a manual)

The hypervisor exposes the PMUv3 common events — `OP_RETIRED`, `OP_SPEC`,
`INST_SPEC`, `BR_RETIRED`, `BR_MIS_PRED_RETIRED`, `STALL_BACKEND`,
`STALL_FRONTEND`, `L1D_CACHE(_REFILL)` — seven counters at once (cycles plus
six). `STALL_SLOT*` and the IMPDEF events read 0. The 2026-08-17 note that only
the generic events count here is out of date.

Microbenchmarks in Go assembly (independent chains, difference method):

| Property | N2 |
|---|---|
| Dispatch | ~5 ops/cycle |
| Integer ALUs | 4 (1-cycle `ADD`, logical, `RBIT`, `CLZ`, `LSRV`, `UBFX`, `CSEL`) |
| `ADD` with an `LSR`-shifted operand | 2 cycles, 2 pipes |
| `ADD`/logical with `LSL` ≤ 4, logical with any shift | 1 cycle |
| Branch units | 2; `CMP`/`TST` + `B.cond` fuse into one op |
| Loads | 3 per cycle; L1 load-to-use 4 cycles (immediate or register offset) |
| Store-to-load forwarding | ~5 cycles |
| Register `MOV` | partly eliminated (~0.7 cycles in a chain), costs an ALU slot |
| Non-encodable 64-bit constant | 4 ALU ops (`MOVZ` + 3 `MOVK`) |
| `bytes.IndexByte`, short match | ~30 cycles flat to 24 bytes, ~34 to 64, 45 at 200 |
| SWAR scan (called), same match | 12 cycles at 1 byte, 22 at 32; crossover ~48–56 bytes |

`Iterate` on the 1.4 KB sample runs at IPC 4.3 (3.9 ops/cycle) with 20% of
cycles backend-stalled; a short quoted field costs 54 cycles against 19 for a
short unquoted one, 42% backend-stalled — the `IndexByte` call's latency.

## What landed

1. **The escape walk, spelled for arm64** (`scan_arm64.go`). The generic walk
   compiles here to 22 instructions per clean word; this one is 16, and it
   re-checks a lane's byte from the register (`byte(w >> (tz & 56))`, one cycle
   on arm64, where amd64 needs the count in `CL`) instead of loading it.
2. **arm64's own `escClean` = 8 and `escGap` = 64**, not 5 and 48: the cheaper
   walk wins out to 64-byte gaps against `IndexByte`'s ~30 cycles a call here.
3. **The sparse scan hands a value back to the walk, once** (`scan_arm64.go`):
   a value the walk declined on arrival whose escaped quotes then come ≤48
   bytes apart — prose followed by embedded JSON — goes back to the walk. This
   closes the "KNOWN GAP" cliff on arm64. Letting any value back after every
   short gap cost 28–34% on alternating short/long gaps (JSON with long string
   values); one hand-back for declined values costs <1% there.
4. **A spare-capacity decoder** (`unescape_spare.go`, selected by the constant
   `runtime.GOARCH == "arm64"`, so amd64 compiles it away). When `dst` has room
   for all of `raw` it writes straight into that room: literal runs up to 32
   bytes are copied inline as overlapping loads-then-stores (no `memmove` call,
   no spills around it), the next-escape probe keeps its constants in registers
   and widens to 8 words, skipping the probe after a run of 64+ bytes until a
   short one turns up, and surrogate pairs decode without a call. Buffers with
   less room than `raw` keep the old loop, so allocation behaviour is unchanged.

## Controls

- A/A (the same binary twice): every row `~`, geomean +0.01%, spread ±0–1%.
- **The core rows are layout, not code.** `Iterate`'s arm64 machine code is
  identical to the baseline's (`bench/asmdiff.py`), yet `IterateOur` measured
  +0.7% — because moving the scans into their own file moved `Iterate` from
  offset 32 to offset 16 of a 64-byte block. With a reachable padding function
  putting it back at offset 0 or 32, every core row matches the baseline within
  ±0.4% (`IterateOur` ±0.0%). The same code retires ~40 fewer ops
  (`OP_RETIRED`) per parse at the 32-byte-aligned offsets: compare-and-branch
  fusion depends on where the pair falls. A consumer's binary places `Iterate`
  wherever its own code puts it, so neither offset is "the" number.
- Mutation check: four deliberate off-by-one errors in the decoder's copies
  each fail `FuzzAppendUnescapeAgainstRef` on its seeds alone; the seeds'
  literal runs were made non-periodic after the first one survived on runs of
  `x`.

## Measured and rejected

- **A SWAR probe for short quoted values** before `IndexByte` (1, 2, 4 or 6
  words): short quoted fields −38%, `DecodeKeyval` −6%, but the realistic line
  `LevelTS` / `GetMany` / `Get/level` +2–10%, since its quoted values are 16+
  bytes and each miss costs 2–5 cycles in context. Same trade as the rejected
  fused value scan (CLAUDE.md), same answer.
- **A fused `TST`+branch key loop** (`orr &^ w & 0x8080… != 0`, exact mask
  rebuilt at the hit): 2 fewer ops per key word; `IterateOur` −2.2%,
  `Get/trace_id` −3.1%, but `GetMany` +0.9%, `DecodeKeyval` +0.9%, second-word
  fields +3.0%, `LevelTS` +0.5%. Geomean −0.06%.
- **Verifying stop bytes from the register** (`byte(w >> (tz & 56))` for `'='`,
  `'"'` and the value stop, no byte loads): +9–11% on short fields — more ops,
  and the chain it shortened was not the bound.
- **The next field's index from the value mask moved up a lane**
  (`TrailingZeros64((hb<<1)&(sw<<1))`, dropping the `+1` from the chain, same
  op count, compiles exactly as intended): −0.3% on short fields.
- **Arithmetic `isSpace`** (no `ADRP`+`ADD` for the table): −2.5% ops, cycles
  flat. **Hoisting the scan constants out of the field loop**: +2–4%, spilled
  across the callback exactly as on amd64.
- **Removal probes** on short unquoted fields: no quote check −0.7%, no
  `vStart > n-1` guard −0.5%, no `'='` verify −1.0%; no callback at all −21%.
  In pure Go the short-field path is within a couple of cycles of its floor
  here; the callback's store-forwarded `i` (~5 cycles) is the one large term.
- **Decoder variants**: an 8-byte copy loop for every run (+66% on 128-byte
  runs; `memmove` wins past ~32 bytes); a fixed 6- or 8-word probe (−25% at
  48-byte gaps, +13–16% at 128); the fast loop inside `AppendUnescape` itself
  (−3 points on every dense row); probe constants reloaded per probe (worse on
  dense rows).

## Reproduce

```sh
git stash; go test -c -o /tmp/before.test .; git stash pop
go test -c -o /tmp/after.test .
python3 bench/counters.py 'Benchmark_IteratePrefixJSON/prefix=064,Benchmark_UnescapeJSONMsg' \
    /tmp/before.test /tmp/after.test --cpu 1
python3 bench/compare.py /tmp/before.test /tmp/after.test --cpu 1 --output /tmp/cmp \
    --bench 'Benchmark_(Iterate|Unescape)' --benchtime 500ms
GOARCH=amd64 go test -c -o /tmp/after_amd64.test .   # and the same at the baseline
python3 bench/asmdiff.py /tmp/before_amd64.test /tmp/after_amd64.test
```

Build both binaries from the same test sources (copy the new benchmark file
into the baseline tree), and run nothing else during a series: this VM has two
cores.
